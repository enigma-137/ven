Code signing policy

Every VEN release is built from the public source code by an automated pipeline. This page explains how releases are made and signed, and who can approve them.

VEN has applied to the SignPath Foundation for free code signing of its Windows releases. Until it is active, Windows binaries are unsigned; see Windows (WSL).

How releases are built

  • All code lives in the public repository github.com/enigma-137/ven under the Apache-2.0 license. VEN contains no proprietary components.
  • Changes reach the release branch through pull requests, which must pass the automated checks (formatting, static analysis, tests with the race detector, cross-platform builds, dashboard build).
  • A release starts when an approver pushes a version tag. GitHub Actions then runs the tests again and builds every platform from that exact commit with the public release workflow. No binary is built or uploaded by hand.
  • Windows binaries are signed only as a step of that workflow, with keys held by the signing service; maintainers never hold the private key.
  • Each release publishes SHA256SUMS next to the archives.

Verify a download

The install scripts check the SHA-256 checksum automatically. To check by hand:

sha256sum --ignore-missing -c SHA256SUMS
Get-FileHash .\ven_X.Y.Z_windows_amd64.zip -Algorithm SHA256

Once Windows signing is active, right-click ven.exe → Properties → Digital Signatures to see the signature.

Privacy

VEN does not send telemetry or usage data anywhere. It only connects to other systems when you ask it to:

  • the VEN server you log in to (ven login, and commands for shared projects such as pull, push and share), which only ever receives encrypted values;
  • GitHub, during ven login, through that server, to learn your username;
  • GitHub release downloads, when you run the install script.

The local vault and the ven ui dashboard stay on your computer.

Report a problem

If you think a VEN binary was not built as described here, or you found a security issue, report it privately through the repository's Security tab ("Report a vulnerability").
